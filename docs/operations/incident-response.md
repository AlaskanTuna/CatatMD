# Incident Response

Use synthetic fixtures when reproducing a defect. Do not put transcript text, note content, credentials, or raw PHI-bearing log lines into an issue or workflow comment.

| Incident                     | Supported Response                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **API Down**                 | Request `https://catatmd-api.onrender.com/api/health` and `https://catatmd.vercel.app/api/health`. A 503 means the database query failed. Review the Render deploy history and privacy-safe JSON logs using the request ID and time. If the API is healthy directly but not through Vercel, inspect the Vercel rewrite and the `deploy` job's `/api/health` assertion. The endpoint does not check the LLM provider.                |
| **Deploy Stuck Behind Main** | Run `gh run list --branch main`, then inspect `verify`, `changes`, and `deploy`. A docs-only change intentionally skips Vercel but may still deploy the API through Render. For a deployable frontend change, inspect for Vercel `BLOCKED`, quota, readiness, alias, or health-check failures. The workflow's author workaround is described in [Deployment](deployment.md). Avoid blind retries when Vercel reports a quota block. |
| **Suspected Secret Leak**    | Rotate the exposed credential at its provider first. Update the matching Render, Vercel, or GitHub Actions setting, then remove the exposed value from the current source or configuration. Render environment changes require a new deploy before the running process uses them. CI scans pull requests and pushes with Gitleaks. Do not paste the credential into an issue or log.                                                |
| **Suspected PHI In Logs**    | Stop copying or sharing the affected log line. Use the request ID and timestamp to limit the search. Restrict access to the log and notify the service owner and clinic data controller for assessment. The logger redacts fields and message text, but developer-authored message interpolation remains a residual risk. The reviewed sources define no log purge or notification automation.                                      |
| **Red-Flag Regression**      | Check the CI `verify` result, which runs the clinical-safety acceptance suite. Roll the Render API back to the previous successful deploy using the [deployment rollback procedure](deployment.md), then fix the rule and pass CI before redeploying. The model may add red-flag candidates but cannot suppress deterministic rule hits. No per-rule production switch is configured.                                               |
| **LLM Provider Outage**      | Check privacy-safe logs for `errorClass: "model_error"`, provider, and model fields. `/api/health` checks only Postgres. There is no automatic retry or production provider fallback. Production rejects Gemini and DeepSeek; keep Qwen configured and have the doctor retry analysis manually after the provider recovers.                                                                                                         |
