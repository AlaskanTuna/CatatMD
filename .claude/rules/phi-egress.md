# PHI And Provider Egress

These rules govern the PHI boundary and LLM and ASR egress paths.

## The PHI Boundary

The trust boundary is a **type**, backed by a runtime check. Both halves matter.

- `Deidentified` (`backend/src/deid/types.ts`) is a branded string. `LLMClient.generate` takes `content: Deidentified`, so passing a raw `string` is a compile error.
- The minting function `markDeidentified` (`backend/src/deid/index.ts`) is **deliberately not exported**. Only `deidentify()` can produce the brand. Do not export it, and do not add a second minting path.
- **A `value as Deidentified` cast is a review-blocking defect**, not a style problem. The compiler cannot stop it; that is exactly why the runtime guard exists.
- `assertNoIdentifiers(content, operation)` (`backend/src/deid/index.ts`) is the runtime backstop: it strips minted tokens, re-runs `detect()`, and throws `DeidentificationError` naming **detector labels only, never matched values**. Preserve that property in any change to the message.
- Detectors are `PATIENT`, `NRIC`, `PHONE`, `ADDRESS`, `DOB`, `MRN`, `EMAIL`, `SCRIPT` (`backend/src/deid/detectors.ts`). Adding a detector means adding fixtures in `backend/src/fixtures/` and a case in `backend/src/deid/deid.test.ts`. Lowering `ACCEPT_THRESHOLD` needs a precision test, not just a recall one.
- **`SCRIPT` tokenises any run of Bengali, Arabic or Devanagari script whole** (#391), because every other detector reads Latin script only and `assertNoIdentifiers` re-runs the same set. Chinese and Tamil are deliberately outside it, since ambient capture hints both and tokenising them would blind the note. A name in either is caught only where a self-introduction or a title marks it (`detectNativeScriptNames`, #418); an uncued one still passes, recorded in `docs/TRD.md` §20.12 and `docs/DECISIONS.md` D-011. Never widen those cues to a bare surname list, since 黄, 白 and 高 are ordinary words too, and never widen them at all without the 134-line precision corpus in `deid.test.ts` still passing unchanged.
- **Identifiers spoken as number words are tokenised by `detectSpokenNumbers`** (#435), because transcription returns an IC as words and every digit detector is blind to that. It mints `NRIC`, `PHONE` or `MRN`, so there is no new label. Its number-word tables in `spoken-numbers.ts` are deliberately not shared with `medications/vocabulary.ts`, so a dose-parser change cannot move the PHI boundary. Anchor and scoring cues are identity words (ic, nric, mykad, kad pengenalan) and phone nouns ("number" only as someone's), never clinic, klinik, medical, physician, pesakit, "call" or "contact", and a run is scored only where the cue sits earlier in its own sentence or the question it answers. A word another detector reads as a cue ends the cued clause, so it is never taken into the token. Never let the cued clause run past a comma into an ordinary word, past an opener or past a sentence end, since that is the #174 failure (masking "500 mg"); a comma before another number word is still the same reading. Digit-only text must stay byte-identical. Tamil number words, phonetic fragments and uncued pairs still pass, recorded in `docs/TRD.md` §9 Spoken Digit Runs. Never change the tables, cues or bounds without the precision corpus in `deid.test.ts` (139 entries) and the precision list in the #435 block still passing unchanged.
- The vault is request-scoped by construction (`RequestTokenVault`, `backend/src/deid/vault.ts`). It is never persisted, never logged, and never a singleton. `deidentify(text, vault)` accepts a caller-supplied vault: **only ever pass one that dies with the request.** A vault that outlives a request is a cross-patient token-collision bug.
- `DEID_FAIL_CLOSED=false` is for unit tests only. Production throws at boot if it is unset or false (`backend/src/config/env.ts`).

## LLM Egress

Maps to OWASP LLM01 Prompt Injection, LLM02 Sensitive Information Disclosure, LLM05 Improper Output Handling, LLM10 Unbounded Consumption.

- `LLMClient` is the **only text egress point**, and the ASR relay (next section) is the only audio one. Exactly one provider SDK import exists repo-wide: `import OpenAI from 'openai'` in `backend/src/lib/llm/openai-compatible.ts`. A second one anywhere is a critical defect.
- All three providers share one adapter class, `OpenAICompatibleClient`. They differ only by `baseURL` and model, selected in `build()` (`backend/src/lib/llm/index.ts`). Do not fork per-provider client code; add configuration.
- API keys are read only through `env` (`backend/src/config/env.ts`). No `process.env` access for a key anywhere else.
- Production boot guards exist for a reason and must not be relaxed: `LLM_PROVIDER=gemini` throws (free-tier terms permit Google to use submitted content for product improvement and human review), and `LLM_PROVIDER=deepseek` throws (PRC hosting, PDPA 2010 s.129 cross-border transfer).
- **The transcript is untrusted input.** A patient or a dictation can contain text shaped like an instruction. The control is the response schema, not the prompt wording: closed schemas, enums, and no free-text escape hatch. Prompt-level defenses fail silently and do not count as controls.
- Every model response is validated with `request.schema.safeParse` inside the adapter before it reaches a route. Never act on unparsed model output.
- Schema failure messages can embed model output. They are currently contained because the route collapses them into a generic `HttpError(500, 'analysis_failed')` and the logger never writes `err.message`. Keep both ends of that.
- **Request bounds are on the constructor, and belong there** (issue #94). `timeout: 60_000` and `maxRetries: 1` replace SDK defaults of 10 minutes and 2 retries, which compounded to roughly 30 minutes per operation because the SDK retries timeouts. Constructor-level, not per-request, so every call path inherits them. Do not move them to a call site, and do not add a provider that bypasses `OpenAICompatibleClient`. Pinned by `backend/src/lib/llm/openai-compatible.test.ts` (OWASP LLM10 Unbounded Consumption).
- **Not built today:** no `AbortController`, so a client disconnect does not cancel an in-flight provider call. That is a quota control, not a bound on hang time; the timeout above is what bounds the hang.

## ASR Egress

**There are three audio egresses, and they are different shapes.** The hosted relay carries a finished recording through the API to ILMU (#154). The browser-held socket streams straight to Soniox, under a key the API mints (#268, `docs/TRD.md` §20.10). The post-Stop upload sends a finished ambient recording straight from the browser to ElevenLabs batch `scribe_v2`, under a single-use token the API mints (#436, `docs/TRD.md` §20.14). Audio cannot be de-identified, so all three are governed by bounds, audit, and per-consultation consent rather than by a gate.

**The Soniox egress has two surfaces, and counting them as one egress is the point.** Ambient capture streams a whole consultation from the Record tab; prescription dictation streams one phrase from the review page (#356, #357, sign-off extended 10/09/26). Same vendor, transport, region and minting route, so nothing about the egress itself moves: what differs is which surface may open it, the recognition config it asks for, and how long a session may run. A **destination** beyond these would still be a new egress and would still need its own sign-off (the post-Stop upload below is the third, signed off separately). A fourth surface on this one would need only a scope extension, and the existing grant is deliberately narrow enough that it would need that.

**Ambient capture may ask for two-way translation, and that is a config on the ambient surface, not a new surface** (#392, `docs/TRD.md` §20.12, scope extension granted 28/09/26, widened to Mandarin and Tamil 06/10/26). The request carries `translation: 'ur' | 'bn' | 'zh' | 'ta'`, valid with ambient only, and `translatedAmbientConfig` selects a written-out config by that closed enum. Three things bind.

- **`turn.text` is always Latin script, English or untranslated Malay, and the other language never reaches a model.** It is Bengali, Urdu, Chinese or Tamil script, which no name detector reads, so it rides only in `TranscriptTurn.otherLanguage`. `backend/src/deid/no-stray-other-language.test.ts` pins that the serialisers omit it and that no backend source names the field, and the `SCRIPT` detector (#391) tokenises such script at the gate whatever a client sends. **Chinese and Tamil script is the exception:** `SCRIPT` deliberately does not read it, so on those two pairs the script guard in `frontend/src/audio/live/bilingual.ts` is what keeps it out of `turn.text`, with no gate-side backstop. It is an allowlist of Latin script on purpose, so a neighbouring script the recogniser picks (Malayalam for Tamil) is caught too. Do not turn it back into a list of scripts.
- **The audit rows record nothing about translation.** With two languages on offer, even a boolean names a likely national origin, and the trail outlives erasure.
- **Malay stays in the translated hints.** Without it, #389 measured "Tak ada" ("no") heard as Bengali and translated "yes".

**The consent rule governs two of the three surfaces, and stopped governing the third on 10/09/26.** On the relay and on ambient capture it is two controls, needing both: a standing preference (the relay's is `engine` in `localStorage`; ambient's is `Consultation.captureMode`, which moved out of device storage and onto the record in #272) and a per-consultation tick in plain `useState` that dies with the component (#155, restored by #254 after #228 briefly collapsed the two into one remembered setting). It is client-side only, because the API still enforces no consent signal. The tick is enforced in `AudioCapture`'s transcribe dispatcher and in `AmbientCapture`'s start dispatcher rather than only on the controls, because the engine can change mid-recording and a disabled button cannot catch that. Never fold the tick back into the preference, and never let either dispatcher fall through to another path instead of refusing.

**Ambient keeps both controls, one of them defaulted since 21/09/26 (D-007, below), and explains neither since 10/09/26** (`docs/DECISIONS.md` D-004). The residency paragraph above its tick was removed on the owner's instruction, so that surface asks to record and names no processor and no region, while the relay's own disclosure is untouched. The "Refine After Stop" switch and the "Refining the transcript" busy label name no vendor either, and the pin tests also reject "ElevenLabs". Two consequences bind.

- **`ConsentGate`'s `disclosure` prop is nullable, and ambient passes `null` rather than omitting it.** The default is the relay's sentence, which says ILMU in Malaysia, so an omission would tell the doctor the wrong country on the one path that streams to the United States.
- **Nothing may point at a sentence that is no longer shown.** The Audio dialog has shipped a claim outliving its control twice already (#228, and its dictation footer after #365). A comment or copy line asserting that the ambient gate names the processor is now false, and a replacement disclosure moved somewhere quieter, a tooltip, a title bar, a settings card, is worse than the recorded absence because the doctor is not reading it at the moment of consent.

**On prescription dictation the count of live consent controls is zero.** It went two, then one, then none inside a single day, every step authorised by @Andersonnn7788 (`docs/DECISIONS.md` D-001).

| Step            | What moved                                                    | Left standing                                              |
| --------------- | ------------------------------------------------------------- | ---------------------------------------------------------- |
| #357            | The gate was built on the review page                         | A device preference plus a per-consultation tick           |
| #363            | `DEFAULT_AUDIO_SETTINGS.dictationEngine` became `'streaming'` | The tick, with the preference pre-set to send              |
| #365            | The disclosure and the tick were removed outright             | Nothing. Pressing Dictate opens the socket                 |
| D-001, 06/10/26 | The device preference itself was removed                      | Streaming always, this device only as the failure fallback |

Three things follow, and none may be quietly undone.

- **The client asserts no consent, because it collects none.** `createLiveSession` takes a `consent` argument rather than hard-coding `true`; dictation omits it, `LiveSessionRequestSchema` permits the omission on that mode alone, and the audit row records `consentAsserted: false`. A client that stopped asking must not keep claiming, or the trail fills with agreements nobody gave. Ambient still passes `true`, and the schema still refuses an ambient body without it.
- **There is no dictation preference any more** (`docs/DECISIONS.md` D-001, 06/10/26). `loadAudioSettings` drops a stored `dictationEngine`, so a device that once chose on-device cannot stay pinned to a choice no screen shows. Every streaming failure still lands on this device or on typing, never silently on the cloud.
- **The relay's `engine` is untouched** and still defaults to the value that sends nothing. **Ambient's capture mode no longer does**, since 21/09/26 (`docs/DECISIONS.md` D-007, #378): a consultation created empty is written `captureMode: 'ambient'`, so that half of the pair ships pre-set to the value that can stream, exactly as `dictationEngine` did on 10/09/26. A create carrying a transcript takes the mode its `source` implies instead, since that capture already happened. What did not move is the tick, which `AmbientCapture`'s start dispatcher still refuses to proceed without and which `LiveSessionRequestSchema` still requires on an ambient body.

**The preference was unreachable from the review page for the whole of #357's life, which is worth remembering before trusting a control to exist because a rule names it.** `AudioSettingsDialog` is the single writer and was mounted only in `CapturePanel`, which renders only while there is no transcript, while the card it governs needs one: the switch and the microphone could never be on screen together, so the rule was two controls on paper and one in the interface. #363 mounted it on both surfaces, and #365 moved the dictation mount into `PrescriptionTheatre`, beside the microphone rather than beside the record of what was prescribed. That mount was removed with the preference on 06/10/26, so `CapturePanel` is the dialog's only mount and its single writer. Falling through to the on-device worker is still forbidden in the same way falling through to the cloud is: it gives a different result with no word that it happened, so an on-device run takes a second deliberate press.

After either path, the transcript text may additionally leave through `LLMClient` as the `draft_turns` operation (`POST /api/asr/draft-turns`, #189). That second egress is text, not audio, so it takes the standard deid gate, and it adds a reconstruction guard (`backend/src/draft-turns/reconstruction.ts`) that re-slices every drafted turn from the input, so the model can label speech but never rewrite it; it carries its own limiter (`draftTurnsRateLimit`) and the `asr.hosted_draft_labelled` / `asr.hosted_draft_failed` audit pair, content never included.

**A third text egress exists and is the one that may propose word changes**: the `transcript_cleanup` operation (`backend/src/transcript-cleanup/`, reached from `POST /api/consultations/:id/transcript-corrections`, #309). It goes deid then `LLMClient` exactly as `draft_turns` does, and `sliceDeidentified` chunks it **after** the gate, never before. What it does not have is a reconstruction guard, because unlike `draft_turns` its whole purpose is to change a word, so the controls are different in kind and all of them live in `backend/src/transcript-cleanup/policy.ts`:

- The model-facing schema carries `original` and `replacement` and nothing else. No `turnIndex`, `start`, `end`, `id` or `source`, so a response cannot assert a position or claim it came from the measured table. Positions are resolved server-side by locating the text, which is also the only approach that survives rehydration.
- An edit is dropped unless its span **overlaps a range the recogniser itself marked uncertain** (`TranscriptTurn.uncertain`, #309). A transcript with no such ranges never reaches a provider at all: the gate is checked before de-identification.
- **A `model` edit is dropped if accepting it would take a red flag away, and the check is differential, not positional.** For each candidate, `applyEditPolicy` runs `evaluateRedFlags` over the transcript that accepting it would produce and refuses any proposal that loses a rule id the transcript raised before. Protecting each fired flag's evidence span is **not** sufficient and was the first design: whether a match becomes a flag depends on text outside the span it matched, since `isNegated` reads 60 characters before it, `isSafetyNetting` 120, and `asserts` and `findDeniedAbility` read the neighbouring turn. A one-word edit turning "Ada" into "Tiada" outside the evidence span silently removes an emergency flag, and every span-based bound admits it. A `source: 'mishear'` proposal is exempt, because the engine already expands the table internally, so a flag matched on a table pair fired because of the corrected reading; `policy.test.ts` pins that as a property rather than an argument.
- **The trigger set is chosen inside `policy.ts`, never passed in.** It was a parameter taking the caller's clinical profile, and that was a hole: `profile.redFlagTriggers` is a filtered slice, the two shipped profiles share one trigger of twelve, and `profileId` arrived in the request body while nothing ties a consultation to the profile it was analysed under. `ALL_REDFLAG_TRIGGERS` is the only safe set, and over-protecting can only drop more model edits. `mergeRedFlags` itself remains untouched.
- Further drops, silent and counted: an ambiguous or absent anchor, a replacement failing the character class, a no-op, a word delta above one, and an oversized anchor.
- `TRANSCRIPT_CLEANUP` gates the whole pass and **defaults to `off`** (`docs/TRD.md` §20.9 makes it conditional on a measurement). Its failure never removes the deterministic proposals: the route answers 200 with `cleanup: 'failed'`, because layer 2 ships unconditionally.

### The Relay, Which Carries Audio

- `backend/src/routes/asr.ts` calling `transcribeWithIlmu` (`backend/src/lib/asr/ilmu.ts`) is the only path audio may take **out of the API**; ambient audio never enters it. No other module may call an ASR provider, and a provider SDK import here is a critical defect. **Two guards enforce this rather than review alone** (issue #172): `backend/src/lib/asr/no-stray-fetch.test.ts` pins the per-file inventory of outbound `fetch` calls in `backend/src`, today exactly two, one in `ilmu.ts` carrying audio and one in `soniox.ts` carrying only a key; and `no-stray-provider-sdk.test.ts`'s package inventory now names transcription vendors alongside LLM ones, so an ASR SDK trips the same guard. The relay is native fetch by design, because ILMU publishes no SDK, which is why the call site needed a guard of its own: an SDK inventory structurally cannot see an egress that imports nothing.
- `ILMU_API_KEY` is read only through `env`. Key unset means the route fails closed and visibly: 503 `asr_unavailable`, before any body is buffered and with no upstream call.
- Nothing is persisted and no content is logged on this path. The audio exists in request-scoped memory only, the log line carries allowlisted fields only, and the audit pair (`asr.hosted_relayed` / `asr.hosted_relay_failed`) records billed seconds, a model id, and a closed failure reason, never content. The upstream response body is never read on a failure path, and a redirect is refused rather than followed, because on this route a request body is patient audio and a response body is a transcript.
- Bounds, all of them deliberate: a route-level `express.raw` cap of 25 MB with `inflate: false` (ILMU's own request cap, unforgeable via `Content-Encoding`), the dedicated `hostedAsrRateLimit` (5/min per `clientKey`), a process-wide in-flight gate (`MAX_CONCURRENT_RELAYS`, 503 when full, because the per-key limiter cannot bound memory), a 120 s `AbortSignal.timeout`, and no retries.
- The success audit write happens before the response and unguarded, so a relay the trail did not record is never observable by a client. Pre-flight rejections (401, 415, 400, our own 413 and 429, busy or key-unset 503) write no audit row because the upstream call was never attempted; every post-attempt failure writes `asr.hosted_relay_failed`.
- **Not built today:** no per-actor or global spend cap. The route is a paid egress reachable by any self-service or guest session, bounded per caller by the limiter and per process by the in-flight gate only, which matches the `analyzeRateLimit` posture. State it as a gap rather than implying coverage.

### The Browser-Held Socket, Which Does Not

Two surfaces open it: ambient capture, and prescription dictation on the review page (#356). Everything below governs both, because both are the same egress.

The browser holds the socket. A WebSocket cannot cross the Vercel rewrite that makes the session cookie first-party (#156), and a direct browser-to-Render socket would lose that cookie, so the audio never reaches our servers at all. **The API does not stop being the policy point.** It decides who may stream, how often, for how long, and what is written down.

- `backend/src/lib/asr/soniox.ts` is the only backend module that may talk to Soniox, and it carries no audio: it mints a temporary key and nothing else. `frontend/src/audio/live/soniox-stream.ts` is the only module in the SPA that may hold a socket. **Three guards enforce this rather than review alone**: `no-stray-fetch.test.ts` pins the backend call at one, `no-stray-provider-sdk.test.ts` scopes `@soniox/` so neither vendor SDK can be imported, and `frontend/src/audio/live/no-stray-websocket.test.ts` pins `new WebSocket(` to that one module. The last is new in kind: it is the first guard covering an egress no server-side check can observe.
- `SONIOX_API_KEY` is read only through `env`. Key unset means both routes fail closed and visibly: 503 `asr_unavailable`, and the capture surface says so and offers press-to-record instead.
- `SONIOX_REGION` is an enum and hostnames are literals in the adapter. Never build a provider hostname from a free-text variable: this value travels to the browser and tells it where to send patient audio. The shared `LIVE_ASR_WEBSOCKET_URL` pattern makes the client refuse any other address even from our own API, and the CSP `connect-src` in `vercel.json` pins the configured host at the platform layer. Redirecting this egress therefore takes a bad response **and** a CSP change.
- The key is bounded twice: `TEMPORARY_KEY_TTL_SECONDS` (30) is how long it may open connections, and the session cap is how long each connection it opened may live. That cap is per mode, 1800 for ambient and 300 for a dictated prescription, because a bound set far above the utterance it governs is not a bound. Dictation was 120 until #365 widened that surface from one drug to a whole prescription sheet in one pass. A cap that fires mid-sentence reaches the browser as a closed socket, so it arrived as a lost connection rather than as a limit, which is a second reason it was the wrong number. **Measured 06/09/26: one key opens more than one connection**, so the second number bounds a stream and not a caller, and the first is what narrows the window. Do not lengthen either without re-reading `docs/TRD.md` §20.10. A server-generated `client_reference_id` is bound to it by the provider and cannot be overridden by whoever holds it, which is what reconciles our audit row against their usage log.
- Nothing is persisted and no content is logged. The audit pair (`asr.live_session_minted` / `asr.live_session_failed`) records a reference id, a model, a region, the mode, the session cap and the client's consent assertion, never content. That assertion is a boolean rather than a constant since #365, and is **derived from the mode rather than read from the body**: `mode === 'ambient' && consent === true`. The schema refinement constrains ambient only, so a body may legitimately arrive as `{ consent: true, mode: 'dictation' }` from an older SPA during the deploy skew that schema exists to tolerate. Trusting the body there would let the trail record an agreement the interface never asked for, which is the one thing this field must not be able to say. The mode is there because one route now mints for two surfaces with different caps, and a row that cannot say which is a row that cannot be reconciled against the provider's usage log. The success write happens before the response and unguarded, so a key the trail did not record is never observable by a client; pre-flight rejections write no row.
- **The provider's `error_message` is structurally unable to leak.** It is omitted from the wire schema in `soniox-stream.ts`, so Zod strips it, and on this path an error body can name a credential. A failure is a value from a closed enum. Never widen that schema to carry vendor text.
- **Not built today:** no global or per-actor spend cap, and the per-session one does not substitute for it because a key can open several sessions; no server-side consent signal, no recovery from a reload (#256, D-010: a dropped socket reconnects on a fresh audited mint and never past the minted cap, but a reload loses an unsubmitted transcript), and no Safari verification. State these as gaps rather than implying coverage.

### The Post-Stop Upload, Which Is Browser-Direct Under A Minted Token

Granted by @Andersonnn7788 on 16/10/26 (#436, `docs/DECISIONS.md` D-014, `docs/TRD.md` §20.14). Scope is post-Stop ambient refinement of untranslated consultations only. It does **not** cover realtime use, dictation, translated sessions, `scribe_v2_medical`, a relay through `/api/*`, a panel naming the vendor, or setting any key.

- **Two modules, no others.** `backend/src/lib/asr/elevenlabs.ts` is the only backend module that may talk to ElevenLabs, and it carries no audio: it mints a `batch_scribe` token and nothing else. `frontend/src/audio/live/elevenlabs-batch.ts` is the only SPA module that may make a cross-origin request.
- **Guards.** Backend `no-stray-fetch.test.ts` pins four entries including `elevenlabs.ts: 1`. `no-stray-provider-sdk.test.ts` scopes `@elevenlabs/` and the `elevenlabs` package. `frontend/src/no-stray-fetch.test.ts` inventories `fetch`, `XMLHttpRequest`, `sendBeacon` and `EventSource` per file, and pins across the whole SPA that only `AmbientCapture.tsx` imports the upload module or mints a batch token. `no-stray-audio-persistence.test.ts` allows the upload module and its one caller.
- **Key and failure.** `ELEVENLABS_API_KEY` is read only through `env`. Unset gives 503 `asr_unavailable` and the config omits `batchRefinement`, so refinement is never offered.
- **Pinned destination.** The host is a literal in the adapter, the shared `BATCH_ASR_UPLOAD_URL` literal is re-checked client-side against the minted session before sending, and `vercel.json` `connect-src` carries the exact host (`elevenlabs.test.ts` pins it). Redirects error, credentials are omitted, and no referrer is sent.
- **Errors cannot leak.** Vendor error bodies are never read on either side, and failures are values from closed enums.
- **Audit.** `asr.batch_session_minted` records the model, the asserted duration and the consent assertion. `asr.batch_session_failed` records a closed reason. Both are written before the response, and neither records content. `consultation.asr_live_used` carries `{ batchUploaded, batchUsed }`.
- **Refinement check.** `POST /api/asr/refinement-check` chooses the trigger set server-side (`ALL_REDFLAG_TRIGGERS`) and forces `source: 'asr_live'` and `labelsReviewed: false`. The speaker is forced too, and differs by side: every live turn the patient's, read by segment and as one whole turn with the hits pooled (the most it could raise), and every refined turn the doctor's (the least), because the doctor-only safety-netting suppression is the one label-dependent reading and reading both sides alike let closing advice mask a dropped report. The SPA sends the refined turns that will be stored, after labelling, never the recogniser's segments. It writes no audit row, as with the live-flags route.
- **Fallback.** Any failure keeps the live transcript with a notice. Refinement can only add a transcript the doctor then reviews. The release depends on #435, because batch writes identifiers as words that the current gate cannot see.
- **Not built today:**
  - The token binds no duration and no provider-bound reference id, so the audit row cannot be reconciled against vendor usage the way Soniox's `client_reference_id` can.
  - Vendor retention of the uploaded audio and transcript sits outside `eraseConsultation`, and is unmeasured.
  - No global or per-actor spend cap. The vendor credit quota on the key and the 5/min mint limiter are the only bounds.
  - No server-side consent signal: the assertion is client-sent and audited.
  - The scope is client-enforced. The untranslated-ambient-only rule, the tick and the acceptance verdict live in the SPA; the mint does not know the capture mode, and the token binds neither the mode nor the vendor parameters, so a caller holding a session could upload other audio under other settings (`scribe_v2_medical`, a webhook) straight to the vendor. The limiter, the audit row and the vendor credit quota bound it.
  - Single use, expiry, the token's query-parameter placement and long-recording behaviour are unmeasured (§20.14).

State these as gaps rather than implying coverage.
